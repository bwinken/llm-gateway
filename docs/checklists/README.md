## 狀態標記

| 標記 | 意思 |
|---|---|
| ✅ | 已有，可以提供證據 |
| 🟡 | 部分做到，或做到了但缺證據 / 文件 |
| ⬜ | 沒有 |
| 🏢 | 組織層級（政策、流程、人員、機房），不在這個 repo；gateway 最多提供證據 |
| ➖ | 不適用（寫明原因） |
| ❓ | 要向別的單位確認 |

## 使用方式

- 盤點日期 2026-11-14。現況來自程式與 `docs/architecture.md`；🏢 與 ❓ 的項目我沒有資料，要由你或負責單位填。
- 標準的控制項編號與名稱是依記憶整理的中文摘要，不是標準原文。正式引用（例如交給內稽）之前，請對照你們持有的標準文本。
- 改到某個控制依賴的程式時，同步更新對應的列。
- 一個缺口完成後，把狀態改成 ✅ 並填上證據位置；roadmap 那一項也跟著更新。

## 盤點時新發現、還沒排進 roadmap 的缺口

寫這些清單時多找到的項目。先列在這裡，由你決定哪些要進 roadmap。

| 暫編 | 缺口 | 出處 |
|---|---|---|
| N-1 | **離職或調職者的 API key 不會自動失效**：帳號從 AuthCenter 移除後，gateway 上的帳號和 key 仍然有效，直到 admin 手動停用。CMP-3（長期未用自動停用）只能擋住沒在用的 key | 27001 A.5.18、A.6.5 |
| N-2 | **沒有告警規則**：Prometheus 指標有了（要開 `METRICS_ENABLED`），但 repo 裡沒有任何 alert rule；排程工作失敗、備份失敗、磁碟、憑證到期都沒有人會被通知 | 可靠度 B |
| N-3 | **沒有定義 SLO / RTO / RPO**：可用率、錯誤率、切換時間的目標都沒寫下來，演練結果沒有比較基準 | 可靠度 G、27001 A.5.30 |
| N-4 | **沒有測試環境（staging）的說明**：改動直接上正式環境；只有搬遷演練用的環境 | 27001 A.8.31 |
| N-5 | **弱點掃描只涵蓋 Python 相依套件**：容器基底映像、OS 套件沒有掃描；沒有 SAST（CodeQL、bandit 之類）；沒有滲透測試紀錄 | 27001 A.8.8、A.8.28、A.8.29 |
| N-6 | **HSTS 還沒開**：nginx 範例裡是註解掉的，`deploy/README.md` 寫的是「之後再開」 | 27001 A.8.21 |
| N-7 | **新模型上線 / 下架沒有檢查清單**：授權、資料去向、評估、價格、guardrail 是否涵蓋 | 42001 A.6.2.4、A.6.2.5 |
| N-8 | **使用者沒有回報管道**：模型輸出有問題、被 guardrail 誤擋、發現安全疑慮時，沒有固定的回報入口 | 42001 A.3.3、A.8.3 |
| N-9 | **沒有容量規劃與壓力測試**：不知道單台能撐多少並行 stream；連線池上限（每 worker 35 條 DB 連線、PG `max_connections=200`）沒有對照實際尖峰 | 可靠度 C、27001 A.8.6 |
| N-10 | **TLS 憑證到期沒有監控**（也包含 AuthCenter 公鑰更換的流程） | 可靠度 A |
| N-11 | **設定檔不在備份裡**：`backup-db.sh` 只備份資料庫；`config.toml`、`client_settings.json`、`.env` 只有搬遷演練的 `1-bundle.sh` 會打包。HA-2 的 rsync 完成後有第二份，但那是同步不是備份（改壞了會一起同步過去） | 27001 A.8.13 |
