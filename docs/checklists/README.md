## 狀態標記

| 標記 | 意思 |
|---|---|
| ✅ | 已有，可以提供證據 |
| 🟡 | 部分做到，或做到了但缺證據 / 文件 |
| ⬜ | 沒有 |
| 🏢 | 組織層級（政策、流程、人員、機房），不在這個 repo；gateway 最多提供證據 |
| ➖ | 不適用（寫明原因） |
| ❓ | 要向別的單位確認 |

## 使用方式

- 盤點日期 2026-11-14。現況來自程式與 `docs/architecture.md`；🏢 與 ❓ 的項目我沒有資料，要由你或負責單位填。
- 四份框架文件的寫法相同：每一項先寫框架的要求，再寫 gateway 的現況、證據、缺口。「要求」的文字來源依框架不同：

  | 框架 | 「要求」用的文字 | 原因 |
  |---|---|---|
  | OWASP LLM Top 10 | 官方英文原文（直接引用） | CC BY-SA 4.0 授權，已從官方 repo 取得 |
  | NIST AI RMF | 官方英文原文，**憑記憶寫的，尚未逐字核對** | 可自由引用，但寫作環境連不上 `nist.gov` |
  | ISO 27001、ISO 42001 | 正式的編號與英文名稱 + 我寫的中文摘要 | ISO 條文有著作權、需購買，不能照抄 |

  ISO 的兩份要交給內稽之前，請對照你們持有的標準核對編號與名稱；需要原文時從標準複製進去。
- 改到某個控制依賴的程式時，同步更新對應的列。
- 一個缺口完成後，把狀態改成 ✅ 並填上證據位置；roadmap 那一項也跟著更新。

## 盤點時新發現的缺口

| REL-2 | 沒有定義 SLO / RTO / RPO | 可靠度 G、27001 A.5.30 |
