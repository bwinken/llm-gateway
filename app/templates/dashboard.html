How to use and test this account {{ 'sends requests for its users (X-On-Behalf-Of)' if app.acts_for_users else 'requests are its own' }}
{% if app.acts_for_users %}

An administrator turned on On behalf of users for this account. Your application signs each person in itself, then sends every request with this account's key and that person's gateway username in X-On-Behalf-Of. The request is then that person's: their daily limit, their model access and their bill.

1. Ask which models that user may use

curl {{ gateway_base }}/models \
  -H "Authorization: Bearer $SERVICE_ACCOUNT_KEY" \
  -H "X-On-Behalf-Of: {{ user.username }}"

2. Send a request for that user

curl {{ gateway_base }}/chat/completions \
  -H "Authorization: Bearer $SERVICE_ACCOUNT_KEY" \
  -H "X-On-Behalf-Of: {{ user.username }}" \
  -H "Content-Type: application/json" \
  -d '{"model": "MODEL_FROM_STEP_1", "messages": [{"role": "user", "content": "Hello"}]}'

To look requests up later by what sent them, add labels of your own to any request: -H "X-Gateway-Tags: module=invoice-ocr,ticket=4821". Up to 16 key=value entries, comma-separated; a value that is not plain ASCII is percent-encoded. They are recorded with the request and go no further.

3. Check where it was billed

The example names you ({{ user.username }}), so the test is on your own budget: after it, Spent today at the top of this page says how much came through {{ app.username }}, and the line above this box counts one more request sent for its users. Nothing is added to this account's own cost.

What is refused

  • 400: no X-On-Behalf-Of header, or more than one username in it. Every request needs it, /models included. Also a malformed X-Gateway-Tags.
  • 403: the username has no account on this gateway (the person opens this dashboard once to get one), is disabled, or is a service account.
  • 429: that user has spent their daily limit. GET {{ gateway_base }}/me with the same two headers says how much they have left.

Keep the key on your application's server, never in a browser or an app people install: whoever holds it can spend any user's budget. A cloud model is served only to a user who has that cloud access.

System One (TypeSafe SDK) POST /v1/systemone

Typed decisions in one forward pass: ask choice, score or yes/no (noul) questions about a state and get calibrated probabilities back instead of text. Use the TypeSafe SDK (pip install typesafe-sdk) with base_url set to the gateway root, without /v1.

from typesafe_sdk import Choice, Noul, Score, TypeSafeClient

client = TypeSafeClient(
    base_url="{{ gateway_base[:-3] }}",
    api_key="{{ user.api_key }}",
    model="{{ systemone_models[0].name }}",
)

result = client.system_one(
    state="I was charged twice for order A-104. Please refund the duplicate.",
    questions={
        "department": Choice(instructions="Which team should handle this?",
                             criteria={"billing": "Charges, invoices", "returns": "Exchanges, refunds", "other": None}),
        "refund_requested": Noul(instructions="Does the customer ask for a refund?"),
        "frustration": Score(instructions="How frustrated is the customer?",
                              criteria=["calm", "frustrated", "very frustrated"]),
    },
)
print(result.choices["department"].choice, result.nouls["refund_requested"].noul)
