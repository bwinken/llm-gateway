Guardrail

Screens the newest user turn of local (vLLM) chat / responses / messages requests with a guard model: in Monitor mode alongside the model call (no added latency), in Block mode before forwarding. Azure and AWS requests are not screened. Runs only when enabled and a base URL is set. The guard model's tokens are never billed. Timeouts, errors and unparsable replies let the request through. Every verdict is recorded in Langfuse (guardrail / guardrail_action scores, guardrail_* metadata).

Built for {{ guardrail_model_family }} (Qwen/Qwen3Guard-Gen-4B): the gateway reads its Safety: … / Categories: … reply. Pointing this at a different guard model requires rewriting the prompt and parsing logic in app/services/guardrail.py.
