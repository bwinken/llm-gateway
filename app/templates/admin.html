Guardrail

Screens the newest user turn of local (vLLM) chat / responses / messages requests with a guard model: in Monitor mode alongside the model call (no added latency), in Block mode before forwarding. Azure and AWS requests are not screened. Runs only when enabled and a base URL is set. The guard model's tokens are never billed. Timeouts, errors and unparsable replies let the request through.
